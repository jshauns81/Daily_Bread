# UI sweep — 2026-08-03

> Also decided 2026-08-03, outside the sweep: **themes are user-bound, not
> family-bound** — the server lists only the caller's own themes, sync scopes
> per user (with an ownership registry for shared devices), and deletion
> propagates: deleting a theme on one device removes it from the server, and
> the owner's other devices notice the id they once synced is gone and drop
> their copies. The Mac gained a context menu on theme rows — its first way
> to delete a theme at all.

First automated pass over every screen, both roles, both platforms. iOS was
walked by the XCUITest screen walker (`apps/DailyBread/UITests/`, run it with
`xcodebuild test` against any simulator — it rides whatever session the device
holds and attaches a screenshot of every stop). macOS was driven by screen
control against the running app. This file is the findings ledger: fix one,
date it, strike it.

## Fixed during the sweep (shipped to master)

- **Theme resolution parsed YAML from disk on every render** — the sign-in
  "freeze". `ThemeStore.resolve` is now memoised; `ThemeLoader.palette` treats
  its cache as authoritative. (`04c9f04`)
- **Opening Settings froze the whole app when the selected custom theme had no
  file** (this exact state shipped on the kid simulator: `db.theme.custom =
  ultraviolet`, no `ultraviolet.yaml`). `resolve` wrote the fallback banner to
  UserDefaults from inside `body`; the AttributeGraph re-dirtied itself
  forever on the one screen observing that key. Resolve is now a pure read,
  the banner is derived (`ThemeStore.fallbackDescription`), and
  `testSettingsHold` stands guard as the regression test. (`9e1b8c3`)

## Open findings, in priority order

1. ~~**Raw usernames everywhere.**~~ **Fixed 2026-08-03.**
   `ApplicationUser.DisplayName` is now the canonical name for every role
   (children backfilled from their profiles; seeder sets parents too). The
   wire's name fields (`UserName` on today, `AssignedUserName`,
   `ApprovedByUserName`) are display strings filled display-name-first at the
   source, member DTOs carry `DisplayName`, and every view prints `.name` —
   usernames only remain in credential contexts (login, account management).
   Follow-on: no UI yet for a parent to edit display names on real accounts;
   until then a member without one shows their username.
2. **Parent iOS Activity: child picker clips at the leading edge.** The
   "Emma_Test ⌄" menu label starts off-screen left. Layout bug, likely a
   missing leading padding/frame on the picker under the large title.
3. ~~**Home renders zeroed defaults while loading.**~~ **Fixed 2026-08-03.**
   Kid Home holds its cards as `.redacted(.placeholder)` until the first
   today fetch answers (nil `today` is the signal; a loaded day with zero
   chores is a real rest day and keeps its visuals), with a quest-card
   silhouette where Next Up will land. The driving card still appears only
   once the server confirms the kid drives — faking one for a non-driver
   would be worse. Parent Home already held behind a spinner; not touched.
4. **Self-approval reads oddly.** Child surfaces show "Approved by Emma_Test"
   for auto-approved chores. When approver == doer (or no approval was
   required), say "Done" and drop the name.
5. **macOS Home: "All done ✨" under children with 0/0 chores.** Vacuously
   true and misleading — Liam/Noah/Olivia had nothing assigned. Show "No
   quests today" (muted) when the denominator is zero.
6. **macOS Home: zero-count status chips.** "+ 0 awaiting approval",
   "! 0 needs help" are noise; show a chip only when its count is non-zero
   (the "9 done today" chip carries the day).
7. **macOS sidebar "Driving" opens a screen titled "Driving approvals".**
   Pick one name. If the screen is approvals + export + parent logging,
   "Driving" is the honest sidebar label and the title should match.
8. **Kid Awards: section header scrolls under the floating tab bar** and gets
   truncated ("STI…"). Content needs bottom padding matching the bar height.

## How to re-run the sweep

```
cd apps/DailyBread
xcodebuild test -project DailyBread.xcodeproj -scheme DailyBread \
  -destination 'platform=iOS Simulator,id=<udid>' -resultBundlePath walk.xcresult \
  -only-testing:DailyBreadUITests/ScreenWalkerTests/testWalkEveryScreen
xcrun xcresulttool export attachments --path walk.xcresult --output-path shots/
```

Sign the device in once by hand; the walker keeps the session (tokens live in
the Keychain and survive reboots). A signed-out device produces one login
screenshot and skips.
